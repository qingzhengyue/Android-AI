## 一、设计背景

本作品属于人工智能与基础教育技术交叉领域。小学 Scratch 教学中，教师需要同时处理任务发布、过程答疑、作品评价和个别化指导；学生又容易在遇到问题时直接索取完整答案。作品聚焦“提示不足”和“答案替代学习”之间的矛盾，设计受教师约束的分层 AI 编程助教。

## 二、主要功能

| 角色 | 功能 | 可验收结果 |
|---|---|---|
| 学生 | 查看学习任务、在 Scratch 工作区编程和保存草稿 | 草稿与任务关联并持久化 |
| 学生 | 请求语法纠错、创意引导和概念讲解 | 记录请求类型、时间和结果 |
| 学生 | 提交作品并获得多维评测 | 输出语法、逻辑、任务匹配、创意四项分数及建议 |
| 教师 | 发布任务、维护班级和学生 | 数据写入本地数据库并刷新界面 |
| 教师 | 配置提示难度、每日次数和完整代码限制 | 学生端按班级策略执行 |
| 教师 | 查看作品、AI 报告并人工复核 | 保留教师评分、评语与审核状态 |

## 三、作品介绍

系统采用 Android 原生 Kotlin 与 Jetpack Compose 构建界面，Room 保存班级、任务、草稿、作品、AI 调用和评测报告，WebView 承载 Scratch 工作区。AI 服务通过兼容接口生成提示与评测；当网络、密钥或返回格式异常时，本地结构评测器解析 Scratch JSON 的 `opcode`，依据事件入口、控制结构、动作类型、积木丰富度给出有边界且可解释的结果。

核心流程：教师发布任务并设置 AI 边界，学生进入任务完成作品，系统保存草稿，学生提交后生成评测报告，教师查看原作品与报告并完成复核。云端同步为增强能力，本地数据链路可独立完成演示。

## 四、主要创新点

1. 教师可配置的分层 AI 提示：把 AI 从直接给答案转为受教学目标约束的过程支架。
2. 云端语义评测与本地结构评测结合：模型负责语义化反馈，本地解析保证断网时仍有确定性结果，并强制校验各维度分数上限。
3. 人机协同评价闭环：AI 初评不替代教师，教师可查看代码、复核分数和给出最终反馈，过程记录可追溯。
